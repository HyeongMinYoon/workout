# 헬스 기록 앱 UI 리파인 브리프

아래 내용을 Claude Design 프롬프트에 그대로 붙여넣으면 된다.

---

## 프로젝트

헬스장에서 운동 중에 쓰는 개인용 웨이트 트레이닝 기록 앱의 UI를 다듬어줘. 이미 동작하는 단일 HTML 파일 프로토타입이 있고, 기능은 확정됐다. 시각 디자인과 정보 계층만 개선하면 된다.

## 사용 맥락

- 갤럭시 Z 폴드 7 커버 화면(약 412 × 940 CSS px) 세로 사용. 최대 폭 440px, 높이 `min(100dvh, 940px)` 고정
- 세트 사이 휴식 60~120초 동안 **한 손으로** 조작한다. 손에 땀이 있고, 다른 손엔 물통이나 바벨이 있다
- 헬스장 조명은 밝고, 화면을 오래 보지 않는다. 한 번 볼 때 1~3초 안에 판단해야 한다
- 다크 모드 고정. 라이트 모드는 만들지 않는다
- 주 5회, 세션당 80분, 세션마다 20~26회의 탭이 발생한다

## 화면 구조

세로 flex 3단 고정 레이아웃.

```
┌─────────────────────────────┐
│ 헤더 (라지 타이틀)            │ ← 스크롤됨
│ 세그먼티드 컨트롤 1 2 3 4 5   │ ← 스크롤됨 (오늘 탭만)
│ ─────────────────────────── │
│                             │
│ 콘텐츠 (카드 목록)            │ ← 이 영역만 스크롤
│                             │
│ ─────────────────────────── │
│ 휴식 타이머 캡슐 (조건부)      │ ← 고정
│ 탭바 4개 (오늘/진행/기록/목록) │ ← 고정
└─────────────────────────────┘
```

## 탭별 내용

**오늘** — 그날의 운동 세션. 준비운동 카드 → 종목 카드 6~7개 → 마무리 스트레칭 카드.
종목 카드 하나의 구성:
1. 헤더: 종목명(유튜브 링크, 재생 아이콘) · 부위 태그 · `4 × 6-10 · 14분`
2. 처방 배너: 상태 태그(`증량 +2.5kg`) + 큰 숫자(`62.5kg × 6`)
3. 지난 기록 줄: `지난 8/1 · 3일 전 · 최고 60kg × 10`
4. 램프업 줄: `램프업 25 · 35 · 47.5 kg × 5회`
5. 세트 행 4~7개: `[원형 체크박스] 60kg × 8 [목표] [수정]`
6. 수정 탭 시 인라인 스테퍼(± 버튼 2줄 + 적용 버튼)

**진행** — 주간 요약 3분할 → 상체/하체/코어 부위별 볼륨 게이지(12개 행) → 컨디셔닝 게이지 → 종목별 추이 → 설명 문단.
부위 행 구성: 부위명 + 볼륨 수치 / 가로 막대(목표 밴드가 채움 막대 위에 겹침) / 세트 이행률 + 목표 범위.

**기록** — 8주 스택 막대 차트(상체/하체/코어 3색) → 부위별 8주 미니 막대 12행 → 세션 로그 카드 목록.

**목록** — 62개 종목 라이브러리. 부위별 아코디언 13개. 각 행에 종목명 + 메타 + iOS 스타일 토글 스위치.

## 상태 색 체계 (현재)

- 처방 배너: 증량 초록 / 유지 파랑 / 디로드 적색 / 완료 보라
- 세트 판정: 목표 도달 초록 / 범위 내 무색 / 미달 주황
- 볼륨 게이지: 후퇴 적색 / 미달 주황 / 목표 초록 / 급증 보라, 목표 밴드는 티일
- 체크박스: 미체크 회색 테두리 / 체크 초록

## 다듬어줬으면 하는 지점

1. **색 의미가 6가지로 늘어나 과부하다.** 상태 색을 3~4개로 정리하고 나머지는 형태·굵기·배치로 구분할 수 있는지 봐줘. 특히 보라(완료/급증)와 티일(목표 밴드)이 다른 맥락에서 각각 쓰이는 게 혼란스럽다.

2. **종목 카드의 시각 계층이 평평하다.** 처방 배너 · 지난 기록 · 램프업이 비슷한 무게의 블록 3개로 연달아 쌓여서, 정작 제일 중요한 "지금 들 무게"가 묻힌다. 운동 중 1초 안에 읽혀야 하는 정보는 처방 무게와 남은 세트 개수다.

3. **세로 스크롤 부담.** Day 5는 종목 7개 × 세트 3~4개라 카드가 매우 길다. 완료된 종목을 접거나, 현재 진행 중인 종목만 펼치는 식의 구조를 제안해줘.

4. **체크박스가 이 앱의 핵심 조작이다.** 34px 원형인데 더 크고 명확해야 할 수도 있다. 체크 전후 대비, 탭 피드백, 진행률이 한눈에 보이는 방식을 제안해줘.

5. **진행 탭의 목표 밴드 게이지 판독성.** 채움 막대 위에 목표 구간을 겹쳐 그리는 방식인데, 밴드가 좁으면 잘 안 보인다. 현재 값과 목표 구간의 관계를 더 직관적으로 보여주는 대안을 제시해줘.

6. **여백과 밀도의 균형.** 정보량이 많아 카드 사이 여백이 부족하다. 반대로 진행/기록 탭은 행이 12개씩 반복되어 단조롭다.

7. **휴식 타이머 캡슐**이 현재는 하단 탭바 위 얇은 바다. 세트 사이 60~120초 동안 가장 자주 보는 요소이므로, 더 존재감 있게 만들되 콘텐츠를 가리지 않는 방식을 찾아줘.

## 제약

- 단일 HTML 파일. React·빌드 도구 없음. 바닐라 JS + 인라인 CSS
- 외부 폰트·아이콘 라이브러리 사용 불가. 시스템 폰트와 인라인 SVG만
- 상태 변경 시 `innerHTML` 전체 교체 방식이라, 복잡한 진입 애니메이션은 매 탭마다 재생되어 부적합하다. CSS transition 수준의 마이크로 인터랙션까지만
- 터치 타깃 최소 44 × 44px
- 애플 HIG 톤을 유지하되 템플릿처럼 보이지 않게. 이 앱만의 시각적 아이덴티티가 있으면 좋겠다

## 산출물

1. 개선된 디자인 토큰 세트(색·타이포 스케일·간격·라운드)
2. 오늘 탭 종목 카드의 재설계안 — 미기록 / 진행 중 / 완료 3가지 상태
3. 세트 행 + 체크박스 컴포넌트
4. 진행 탭 볼륨 게이지 대안 2가지
5. 휴식 타이머 대안
6. 각 제안에 대해 왜 그렇게 바꿨는지 한 줄 근거

먼저 방향을 2~3개 제시하고, 내가 하나를 고르면 그때 상세 시안으로 들어가줘.
